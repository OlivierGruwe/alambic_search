Droits

Un document est visible par un utilisateur quand ils ont au moins un « principal » en commun (un groupe, un SID Windows, son identifiant), et qu'aucun refus ne s'applique. Les droits sont appliqués avant toute recherche et avant le LLM.

D'où viennent les principaux

Côté document : le connecteur traduit les droits de la source

SourceCe que porte le document
Partage Windows (SMB)Les SID des comptes et groupes des ACL NTFS, refus compris
SharePoint / OneDriveLes SID des comptes et groupes synchronisés depuis l'AD ; les groupes de site, traduits en groupes AD par le réglage « Groupes de site → groupes AD » de la source
Alfresco, GED CMISGROUP_Compta → le nom « Compta » ; un utilisateur → u:identifiant ; « tout le monde » → Tout le monde ; groupes de site et rôles internes → ged:… (personne ne les a)
Dossier, FTP, S3Les noms de groupes écrits dans les règles par dossier de la source

Côté utilisateur : l'annuaire ou le jeton

OrigineCe que reçoit l'utilisateur
Annuaire AD (LDAP){% if has_identity %} actif{% endif %}Son SID, les SID de tous ses groupes (imbriqués compris), leurs noms, u:identifiant, Tout le monde
Jeton Keycloak{% if oidc_groups_mode == 'jeton' %} actif{% endif %}Les noms de groupes du jeton, u:identifiant, Tout le monde — pas de SID : partages Windows et SharePoint invisibles
Keycloak + annuaire{% if oidc_groups_mode == 'annuaire' %} actif{% endif %}Connexion par Keycloak, groupes lus dans l'AD : comme la première ligne
